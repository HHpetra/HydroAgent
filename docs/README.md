# 架构说明

HydroAgent 是纯 Python MCP 服务项目：不包含桌面壳、launcher 或 dsh profile。MCP 宿主通过 stdio 加载服务。

- 只写架构和关键原理，不写实现细节与过程性 spec。
- 具体实现以阅读代码为准。

## 分层

| 层 | 位置 | 职责 |
| :--- | :--- | :--- |
| MCP 服务 | `src/hydro_agent/servers/reservoir_info.py` | 只读水库资料与过程序列 |
| MCP 服务 | `src/hydro_agent/servers/floodroute.py` | 静库容调洪与调度方案计算 |
| 领域核心 | `src/hydro_agent/core/` | SCS-CN 产流、SCS 单位线汇流、河道洪水演进、静库容调洪（共享） |
| 数据 | `tests/fixtures/`、`HYDRO_AGENT_DATA_DIR` | 可复现样例与运行资料 |
| 宿主 | 任意 MCP 客户端 | stdio 启动、工具调用与结果展示 |

## 关键数据流

1. 宿主先调用 `reservoir-info` 的 `list_reservoirs` / `get_flood_routing_inputs`。
2. 宿主把返回的 `as_of`、`z0`、入库过程、库容曲线、出流侧（`discharge` 或 `gates`）与实测过程原样传给 `floodroute`。
3. `floodroute` 返回特征值与过程序列；过程图、调度建议与最终汇报由宿主组织。

## 场景时钟

所有工具以 `as_of` 为时间基准，不使用系统时间；`as_of` 从资料工具返回并原样传递。

## SCS-CN 产流

流域净雨在 `hydro_agent.core` 中按一场雨的累积降雨计算：先得到累积净雨，再差分出逐时段净雨。初损在整场雨里只消耗一次。按场景时刻截取余雨时，先算完整场雨，再取该时刻之后的增量。直接相连的不透水面积默认不扣损。

## SCS 单位线汇流

净雨经 SCS 三角形单位线离散卷积得到直接径流，叠加基流后成为入库过程。离散纵标按 1 mm 净雨对应 `1000 F` m³ 重标定，`F` 为流域面积（km²）。接合时刻只卷积其后的余雨，并在该时刻与已有入库连续。给出场景时刻时，输出至少铺满其前后各 12 h；没有过程值的时刻为 0，不把基流抄进空档。资料退化时由洪峰和达峰小时数生成概化三角形入库；未给退水历时则涨退比为 1:2。`hours_to_peak` 从场景时刻起算，优先于手册涨水历时。

## 静库容调洪

水库调洪在 `hydro_agent.core` 中按静库容逐时段做水量平衡。库容曲线在坝前水位与库容之间严格单调，可以双向插值。出流只取一套关系：无闸走泄流曲线，有闸由闸门几何在堰流与孔流之间计算；两套同时给出或同时缺省都拒绝。场景时刻的坝前水位是起调水位。该时刻之前不重新积分，实测水位、出库和开度按观测时间原样保留，包括前一个日历日。该时刻及之后用梯形水量平衡求时段末水位。调度可以是自由溢流、开度时刻表、恒定泄量、预泄、控安全泄量、控最高水位、敞泄或闸门故障。预泄把水位降向堰顶，洪峰过后只持平汛限，不再降回腾库目标；腾库目标低于堰顶时抬到堰顶。上游在失联时刻与场景时刻之间缺测时，由实测水位和出库反推入库，再与失联前的实测入库、场景时刻之后的预报入库衔接。给出场景时刻时，输出至少铺满其前后各 12 h。

## 河道洪水演进

上游测站流量在 `hydro_agent.core` 中演进到坝址。马斯京根法用槽蓄方程逐时段算出流；步长短于稳定下限时，河段拆成等分子河段再级联，子河段数取稳定区间内最接近 `ceil(K/Δt)` 的整数。变动滞时按流量计算测站滞时，流量大则滞时短。末次到达时刻是场景时刻加上该时刻流量的滞时，不要求它落在输出步长上；`(as_of, t_join]` 内的网格点由到达过程线性插值。场景时刻以前用坝址实测入库；其后到末次到达时刻只用测站演进，不做斜率外延；再往后只卷积区间结束时刻晚于接合时刻的余雨，初损仍按整场雨计，并在接合点与演进末值连续。余雨单位线的支撑结束以后，以及接合后没有正的余雨净雨时，场景窗口里的空档为 0，不再另做退水曲线。给出场景时刻时，输出至少铺满其前后各 12 h。

## 边界

- stdout 只写 MCP 协议消息，日志写 stderr。
- 两个服务共享 `hydro_agent.core`，不互相 import。
- 不 fork 官方 MCP Python SDK；不引入 dsh、Node.js 或 TypeScript 工程。
